# 当前迁移设计

NeoCC 采用 TinyCC 算法的逐步职责迁移。当前阶段完成源文件、token 存储、预处理工作状态、
语义符号存储、符号栈/作用域层级、表达式值栈/常用类型、作用域帧/清理链入口、
当前函数上下文及 switch/case 资源的职责迁移，尚未完成整个编译器的对象化重写。
`src/compiler/` 保存活跃的 TinyCC 衍生算法，
`tinycc/` 仅用于差分基线，不参与 `neocc` 的链接或运行。
迁入范围、基线提交和原文件校验值见 `tinycc_sources.json`。

## 已实现的所有权

| `symbols` 的 `em_symbols` | 语义符号分配块与回收链、五类符号栈头及当前作用域层级；普通符号记录有效至归还、reset 或末次关闭 |

| `functions` 的 `em_functions` | 当前函数类型/名称/起始位置、变参/旧式标志、局部栈偏移、隐式结构体返回地址、返回跳转链和临时栈槽缓存；名称与类型仅为借用 |

`source` 继承唯一 NEOioic 根节点。`crt_source` 由 OpenOICC 生成，构造区使用
配套 `openoicc/construct.h`，布局与席位边界在构造阶段校验。
宿主不销毁仍有引用的图，外部存储仍由调用者管理。

`include/neocc/source.h` 定义进程内消息；指针不是序列化字段。push/pop 消息使用
`memcpy` 读取/写入，支持未对齐缓冲，检查输入长度、输出容量和实际输出数量。
push 成功才转移句柄；失败由调用方关闭。fd 0 为借用标准输入，fd -1 为内存输入。
文件名最长 1023 字节，超过后明确失败，不再静默截断。
流式缓冲沿用 8192 字节及 TinyCC 的 EOB 标记，保留包含栈、token 标志和行号语义。

真实文件名在 `#line` 首次修改前通过对象保存；其分配和释放使用同一 C 分配器。
末次关闭清空未弹出的所有缓冲；共享打开时中间关闭保留资源。
`RN_CLOSEPARTIAL` 按运行时协议仅可继续关闭，禁止继续业务或销毁。

## Token 存储

`tokens` 负责标识符驻留和 ID 分配；算法模块经 VO 请求驻留、查询和宏流调整，
不再持有全局 `table_ident`、`hash_ident`、`tok_ident` 或 TinyAlloc 链。
`include/neocc/tokens.h` 定义进程内消息。查询返回借用 token，新增名称或扩展索引表
不使已有 token 失效；借用持续至 reset 或末次关闭。token 内的语义符号链接由解析器
管理，符号记录的存储归 symbols。驱动先清理语义/宏定义栈及符号链接，再重置符号存储，
随后释放宏展开栈并重置 token 存储；语义规则仍留在解析算法中。

对象保留 TinyCC 的哈希和池化算法边界。宏流按 `max_align_t` 对齐，支持尾部原地扩展、
空块复用和超大块回收；尺寸计算检查溢出。调整失败保留旧存储，复制限制为旧逻辑长度，
关闭兜底释放所有块。与原分配器不同，失败时不会先回退旧尾部游标。宏流指针必须来自
同一对象的有效分配；不承诺检测任意伪造或失效指针。

`source`、`tokens` 均独立继承 NEOioic，构造区由同一版本 OpenOICC 生成。
编译上下文创建失败清理已经取得的对象；末次关闭分别释放各自资源，宿主只回收图和 OID。

## 语义符号存储与栈

`symbols` 独立继承 NEOioic，拥有按 TinyCC 约 8192 字节一批分配的符号数组及回收链。
分配、归还和 reset 均通过 VO；沿用原池内逆序挂链和 LIFO 复用，不把每个符号包装成对象。
删除 sym_free_first、sym_pools、nb_sym_pools 和 SYM_DEBUG 独立分配分支。
符号池用同一 C 分配器成批 malloc/free；扩容失败保留旧块和旧符号，返回 VO 后再诊断跳转，
不经过旧编译器会直接 exit 的致命分配器，也不再为池维护独立的可增长指针数组。

`include/neocc/symbols.h` 声明 `struct neocc_symbol`、`struct neocc_type` 及两种属性记录，
替代 Sym/CType typedef；字段顺序、位域类型、符号语义与目标 ABI 沿用原实现。
分配返回未初始化的普通记录，由既有 sym_push2 等算法初始化；归还消息借用一个有效符号指针，
该指针必须来自同一对象且仅归还一次，不承诺检测任意伪造、跨对象或重复归还的指针。
消息经 memcpy 处理，支持未对齐缓冲，失败不发布符号或修改回收链。

同一对象还拥有 global、local、宏定义、global label 和 local label 五个栈头以及当前
`local_scope` 层级。push/copy/top/drop/move/scope 消息经 VO 执行，算法只持有借用的栈顶、
边界和目标记录，不再定义对应全局变量。move 保持“从源栈任意位置摘除、按需在原位置留下
复制记录、再挂到目标栈顶”的 TinyCC 语义；五个栈顺序、符号回收链和 token 表的
`sym_identifier`/`sym_struct`/`sym_define`/`sym_label` 链接仍共同决定名字可见性。

宏定义文本、token 表和标签代码生成仍属对应算法；对象只拥有栈头与记录存储。算法在
drop/reset 前先撤销 token 链接：普通符号与宏定义逐个退栈，标签在正常收尾时检查并发射，
错误收尾由 `label_discard` 清除链接，最后才 reset 对象。正常和错误收尾先清理内联函数、
符号/宏定义/标签栈、switch 与其他借用，再 reset 符号池；共享打开的中间关闭保留池，
部分关闭保留资源供重试，末次关闭兜底释放所有块和栈状态。
编译会话组合八个资源对象，创建失败清理已取得的对象，销毁时先关闭 switches、functions、scopes、expressions、preprocessor，
再关闭 symbols、tokens、source。

## 表达式值栈与常用类型

`expressions` 独立继承 NEOioic，拥有 512 个表达式值及一个真实哨兵、栈顶和
`int_type`、`char_type`、`char_pointer_type`、`func_old_type`。容量沿用 TinyCC，
空栈指向数组第零项，算法基址为 `values + 1`，保留预处理常量求值的哨兵行为。
删除 `vtop`、`_vstack`、四种常用类型的全局定义以及 `SValue` typedef，
用 `struct neocc_expression_value` 保持原布局与载荷；不把每个表达式值包装成运行时对象。

工作区包含宿主 long double，首次打开以 calloc 独立分配，末次关闭释放；
共享打开保留存储，部分关闭保留资源供重试。通过 VO 借用工作区、reset 清零全部数组、
类型与符号引用并恢复哨兵栈顶；reset 前后地址稳定，关闭再打开需重新借用。
指针消息经 memcpy 输出并校验容量、实际数量，属于进程内契约。
算法继续直接生成代码，push/pop、寄存器分配和类型构造规则保持原语义；常用目标类型
在 `tccgen_init` 根据目标常量、char 选项和 symbols 记录初始化，不混入对象的宿主布局逻辑。

正常和诊断跳转后的 `tccgen_finish` 在 reset 符号池前清除表达式工作区引用，
避免保留已释放类型/符号和旧栈顶。编译会话创建失败关闭已取得图和已打开的基节点。
新回归覆盖对象隔离、宿主对齐、数组两端、共享打开、未对齐/短消息、reset、部分关闭、
再次打开、两个新增分配失败点，以及真实值栈耗尽诊断后的资源清理和新会话恢复。
现有算法仍从 `tcc_state` 取得当前工作区，不宣称已可重入或并行。

## 作用域帧与清理链入口

`scopes` 独立继承 NEOioic，拥有 `neocc_scope` 帧、当前/根/循环入口及
`all_cleanups`、`pending_gotos` 链头，删除原文件级作用域结构及五个入口。
`include/neocc/scopes.h` 定义进程内指针消息；借用工作区内嵌于对象成员块，
不含超出运行时成员对齐要求的字段。reset 保持工作区地址，关闭后需重新借用。

ENTER 经 VO 分配或复用普通帧：空栈建立零初始化根帧，嵌套帧继承当前帧并清零
本层 VLA 数量。EXIT 只接受本对象栈顶且已解除循环入口引用的帧，恢复父帧并回收。
帧只在嵌套深度增长时 malloc，按 LIFO 复用，直到 reset/末次关闭统一释放；没有新增
固定深度上限，也不把每一层包装成运行时对象。失败不发布帧或改变原状态，诊断在 VO 返回后执行。

TinyCC 的 VLA 栈恢复、cleanup/goto、标签和直接代码生成算法仍在 `tccgen.c`。
帧中符号记录由 symbols 拥有，break/continue 目标借用解析调用的局部变量；短作用域
只在局部保存符号边界，不建立完整帧。正常函数结束出栈根帧，诊断跳转后由独立的
active/available 链回收，避免遍历失效的解析器栈地址。`tccgen_finish` 先清理 switch
和标签，再 reset scopes、functions、expressions，最后 reset symbols；清理/goto 链头不重复拥有符号记录。
对象回归覆盖 258 层、继承/复用/隔离、非法出栈、共享打开、部分关闭及各层分配失败；
会话回归注入五处根/嵌套帧分配失败，检查清理链、goto 链和 VO 记录清空及新会话恢复。

## 当前函数与临时栈槽

`functions` 独立继承 NEOioic，拥有内嵌的 `neocc_function` 工作区和八项临时栈槽缓存。
原 `func_vt`/`func_var`/`func_vc`/`func_ind`/`func_old`/`funcname`、`loc`、`rsym`、
临时槽数组和数量的全局定义及共享声明已删除。算法经 VO 借用工作区，BEGIN 清除旧缓存并
接收初始函数上下文；名称借用 tokens 字符串、类型借用 symbols 记录，均不重复分配。
旧式参数声明先使用工作区的 type，函数开始时再替换为返回类型。后端与调试模块使用同一
会话的工作区；调试模块沿用已有显式会话参数。指令游标和后端专有补丁/ABI 状态未纳入此对象。

TEMP 经 VO 保留 TinyCC 的首次匹配算法：表达式算法从值栈 r2 标签计算占用位图，
对象选择大小/对齐足够且未占用的缓存项，否则向下对齐局部栈并登记新槽。缓存满后继续
分配未缓存槽，不限制函数大小；保留原八项缓存、short 大小/对齐字段及目标寄存器标签语义。
用 int64_t 检查减法/对齐结果可表示为 int 后才更新状态；无效尺寸、对齐、消息或栈偏移溢出
均不改变缓存/偏移，错误正常返回 VO 后再由编译算法诊断。

函数结束在调试/异常帧与符号大小输出完成后 reset；正常或 longjmp 收尾在 debug、switch、
标签清理后 reset scopes/functions/expressions，再释放 symbols 与 tokens 存储。
reset 清除类型/名称借用、返回跳转链和全部缓存，保留工作区地址；关闭再打开需重新借用。
对象回归覆盖缓存复用、占用、满缓存继续分配、对齐、边界溢出、无效消息与生命周期；会话
回归在变参/结构体返回/VLA/寄存器溢出后触发真实诊断，观察非空工作区，再核对清理及新会话恢复。

## Switch/case 上下文与资源

`switches` 独立继承 NEOioic，拥有内嵌的当前链入口及普通 switch/case 记录和索引数组。
删除 `cur_switch`、文件级 `switch_t/case_t` 定义和解析器内的直接分配释放路径；
`include/neocc/switches.h` 定义进程内消息与借用边界，算法经 VO 借用 `TCCState.switch_state`。
ENTER 推入零初始化记录，CASE 追加零初始化 case 并按需几何扩容索引，REMOVE 用于
范围合并时删除记录并压缩数组，EXIT 仅允许退出本对象栈顶。长度、容量及尺寸计算检查
整数范围；分配失败保留当前链、旧索引及全部已有 case，返回 VO 后才诊断跳转。

包含宿主 long double 的 switch 值保存在 malloc 分配的普通记录中，保证自然对齐；
NEOioic 成员块只保存指针。表达式类型借用 symbols、作用域借用 scopes、break 目标
借用解析调用的局部变量，不重复拥有。正常退出释放当前记录及其 case，RESET 和末次
关闭兜底释放整条链；清理不解引用这些借用，因此诊断 longjmp 后也不访问失效的局部地址。
reset 先于 scopes/expressions/symbols 的 reset，共享打开的中间关闭保留资源，部分
关闭仅重试清理，再次打开重新借用入口。

TinyCC 的有符号/无符号排序、重复 case 检查、相邻范围合并、线性/二分查找及直接
分支生成算法保留在 tccgen.c。qsort 回调按 switch 值的符号属性选择纯比较函数，
不再从当前会话入口查找排序模式；其余语法算法仍使用全局会话入口，不宣称可重入。
新增普通/故障对象回归覆盖 258 层、case 增长、未对齐消息、非法退出、对象隔离、
reset、部分关闭、构造/记录/索引分配失败。编译会话验证嵌套 switch 内的分配失败、
重复 case/default、无效表达式与诊断收尾；语义样例纳入运行、预处理、三种调试配置
下的目标字节差分和阶段自举。

## 预处理工作状态

`preprocessor` 独立继承 NEOioic。编译上下文经 VO 借用 `neocc_preprocessor` 工作区，
借用地址在对象打开期间及 reset 前后稳定；末次关闭释放工作区，再次打开后需重新借用。
reset 清零当前 token/值和源游标，使字符串内容和 arena 引用失效。
算法继续沿用 tccpp.c，不创建逐 token 对象。宏流入栈/退栈经 VO 保存和恢复流指针、
源行号及释放策略；退栈返回需回收的流，由编译算法经 tokens 的 VO 释放。
宏流及流节点的分配块仍归 tokens，预处理对象只拥有链和两个可复用流描述符。

预处理对象初始化与重置 EOF/字节分类表，汇编模式及 `$` 选项在当前工作区调整；
工作区还拥有解析字符串、token 拼写、数字缓冲、预定义文本、展开/回退流、
预处理表达式诊断状态、调试 token 和 `__COUNTER__`。这些文件级全局定义已删除。
当前 token/值、借用源游标和 PP_DEBUG 缩进也归此工作区所有，原 `tok`、`tokc`、
`file`、`indent` 全局定义已删除。语法、汇编和调试模块借用同一会话的 token/值；
源对象 push/pop 正常返回 VO 后，驱动更新该会话的借用源游标。搜索路径展开直接使用
显式会话，诊断在退出全局入口后仍使用其局部会话，避免重新读取空的 tcc_state。
算法仍通过现有 tcc_state 取得会话，因此尚未可重入或完整脱离全局入口。

常量载荷共用 `union neocc_value`，替代旧 CValue typedef，保留成员顺序、宿主
long double 表示和 token 流字数算法。工作区含 long double，宿主对齐可能超过
NEOioic 成员块的对齐上限，因此 em_preprocessor 只保存拥有指针，首次打开以
calloc 独立分配自然对齐的完整工作区，不修改运行时或放宽构造辅助的布局检查。
分配失败由 VO 返回，调用方关闭已打开的基节点后回收对象；未取得工作区时拒绝业务。
共享打开和中间关闭保留地址及内容，部分关闭保留资源供重试，末次关闭才释放。
宿主载荷的大小不等于目标 ABI 的 long double 大小；当前 Windows PE 目标仍沿用 8 字节语义。

通用字符串改用 `struct neocc_string`；reserve 使用 C 分配器，失败保留旧指针、长度和容量，
几何扩容检查 int 上限。正常与诊断跳转路径均通过同一 clear 释放，不混用旧编译器
可替换分配器或 MEM_DEBUG 元数据。局部字符串清理栈登记字符串本体，跳转前统一 clear。
参数/路径列表向旧编译器分配域移交内容时复制字符串，避免将 C 分配器的指针交给
可替换分配器释放。局部清理栈仍待随语法状态迁移。预定义文本作为对象成员存活，避免创建命令行输入缓冲
失败时跳过局部字符串释放。末次关闭兜底释放工作字符串，共享打开的中间关闭保留状态。

正常与失败收尾均先释放语义符号、展开宏栈并弹出源文件，再重置预处理工作区，最后
重置 tokens arena；不能先释放 arena 再访问宏流或解析字符串。会话销毁先关闭
switches、functions、scopes、expressions、preprocessor，再关闭 symbols、tokens/source。构造区与阶段测试覆盖八个对象。

## 错误退出

TinyCC 的诊断跳转保留在编译驱动中。对象方法不调用会 `longjmp` 的编译器诊断；
先正常返回，经 VO 撤销访问记录，再由驱动报告错误/跳转。首次源缓冲失败也关闭已打开
的句柄。预处理对象首次打开时分配并初始化工作区，驱动在首次算法分配前启用清理；
主文件尚未成功时只清理输入链。
预定义头加载前先初始化代码生成清理所需状态，避免早期错误使用上次编译遗留指针。

失败测试注入主文件、命令行伪文件和预定义头三处缓冲分配失败，随后创建新会话编译；
检查输入链为空、访问记录归零、进程句柄数不增加。源对象另测构造区、队列、真实
文件名分配失败和可重试部分关闭。预处理测试覆盖嵌套流、未对齐消息与部分关闭；
会话故障测试还覆盖八个对象构造、两个工作区分配、工作字符串与索引扩容失败，以及三个符号池分配失败点；
符号 push 失败不改变栈，标签未定义跳转后的错误清理会撤销符号/token 借用。测试检查池、五类栈头、
作用域层级和 VO 记录清空，整体分配/释放数量及新会话恢复编译。

## 后续迁移

活跃构建已删除 `ONE_SOURCE` 聚合分支，预处理、语法、汇编、后端、链接和装载均为
独立编译单元；目标头的 `TARGET_DEFS_ONLY` 仍用于既有 ABI 常量。
源游标、当前 token/值、符号栈头、作用域层级、作用域帧与清理/goto 链入口已归对象；
当前函数上下文与临时槽缓存已归 functions，switch/case 链与资源已归 switches；`tcc_state`、初始化器工作状态、
指令游标/代码抑制和目标后端专有状态仍有全局或文件级定义，尚未获得并行或重入保证。
不得把独立编译、自举或八个资源对象误称为全部状态迁移完成。

下一职责按原算法边界迁移剩余语法与代码生成工作状态，并逐步显式传递预处理算法的协作上下文，
随后迁移目标代码生成、链接输出和装载资源。跨对象操作使用 `vo_*`，通过参数传递
协作上下文，不增加新的全局服务定位器，也不把所有状态堆进一个会话对象。
每步替换活跃路径、删除被替代实现并重跑差分和阶段稳定性验证。

## 参考树独立性

根构建只在参考树存在时声明可选 `tinycc_baseline` 目标。`tests/independent.py` 每次创建
新的源码副本，只复制 NeoCC、运行库、仓库内运行时/生成器及必要回归输入，不复制
`tinycc/` 或既有构建缓存；在该副本中构建、执行十八组回归和阶段自举。
这验证文件和工具依赖的独立性，不等于剩余算法已经完成对象化迁移。
