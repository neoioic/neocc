# 当前迁移设计

NeoCC 采用 TinyCC 算法的逐步职责迁移。当前阶段完成源文件和 token 存储资源对象化，
尚未完成整个编译器的对象化重写。`src/compiler/` 保存活跃的 TinyCC 衍生算法，
`tinycc/` 仅用于差分基线，不参与 `neocc` 的链接或运行。
迁入范围、基线提交和原文件校验值见 `tinycc_sources.json`。

## 已实现的所有权

| 所有者 | 资源及有效期 |
| --- | --- |
| `src/main.c` | CLI 选项和输出流，创建/销毁编译上下文 |
| 编译上下文 | 组合并打开独立的 `source`、`tokens` 对象，销毁前完成关闭 |
| `source` 的 `em_source` | 唯一的输入缓冲栈顶，拥有整条链、fd > 0 和真实文件名副本 |
| `tokens` 的 `em_tokens` | 标识符哈希/索引表、稳定的 token 实例、标识符实例与宏流的分配块 |
| 解析器 | 借用当前缓冲及其字段，弹栈后不得继续持有旧指针 |
| `src/host/` | 创建选择、单线程 OID 分配与回收、宿主调用者身份 |
| NEOioic | 接口分派、访问记录、继承根和队列；保持独立 |

`source` 继承唯一 NEOioic 根节点。`crt_source` 由 OpenOICC 生成，构造区使用
配套 `openoicc/construct.h`，布局与席位边界在构造阶段校验。
宿主不销毁仍有引用的图，外部存储仍由调用者管理。

`include/neocc/source.h` 定义进程内消息；指针不是序列化字段。push/pop 消息使用
`memcpy` 读取/写入，支持未对齐缓冲，检查输入长度、输出容量和实际输出数量。
push 成功才转移句柄；失败由调用方关闭。fd 0 为借用标准输入，fd -1 为内存输入。
文件名最长 1023 字节，超过后明确失败，不再静默截断。
流式缓冲沿用 8192 字节及 TinyCC 的 EOB 标记，保留包含栈、token 标志和行号语义。

真实文件名在 `#line` 首次修改前通过对象保存；其分配和释放使用同一 C 分配器。
末次关闭清空未弹出的所有缓冲；共享打开时中间关闭保留资源。
`RN_CLOSEPARTIAL` 按运行时协议仅可继续关闭，禁止继续业务或销毁。

## Token 存储

`tokens` 负责标识符驻留和 ID 分配；算法模块经 VO 请求驻留、查询和宏流调整，
不再持有全局 `table_ident`、`hash_ident`、`tok_ident` 或 TinyAlloc 链。
`include/neocc/tokens.h` 定义进程内消息。查询返回借用 token，新增名称或扩展索引表
不使已有 token 失效；借用持续至 reset 或末次关闭。token 内的语义符号链接由解析器
管理，因此驱动先释放符号栈、宏展开栈，再重置 token 存储；不把语义所有权转交存储对象。

对象保留 TinyCC 的哈希和池化算法边界。宏流按 `max_align_t` 对齐，支持尾部原地扩展、
空块复用和超大块回收；尺寸计算检查溢出。调整失败保留旧存储，复制限制为旧逻辑长度，
关闭兜底释放所有块。与原分配器不同，失败时不会先回退旧尾部游标。宏流指针必须来自
同一对象的有效分配；不承诺检测任意伪造或失效指针。

`source`、`tokens` 均独立继承 NEOioic，构造区由同一版本 OpenOICC 生成。
编译上下文创建失败清理已经取得的对象；末次关闭分别释放各自资源，宿主只回收图和 OID。

## 错误退出

TinyCC 的诊断跳转保留在编译驱动中。对象方法不调用会 `longjmp` 的编译器诊断；
先正常返回，经 VO 撤销访问记录，再由驱动报告错误/跳转。首次源缓冲失败也关闭已打开
的句柄。驱动在预处理首次分配前建立可清理的游标和缓冲状态；主文件尚未成功时只清理输入链。
预定义头加载前先初始化代码生成清理所需状态，避免早期错误使用上次编译遗留指针。

失败测试注入主文件、命令行伪文件和预定义头三处缓冲分配失败，随后创建新会话编译；
检查输入链为空、访问记录归零、进程句柄数不增加。源对象另测构造区、队列、真实
文件名分配失败和可重试部分关闭。

## 后续迁移

活跃构建已删除 `ONE_SOURCE` 聚合分支，预处理、语法、汇编、后端、链接和装载均为
独立编译单元；目标头的 `TARGET_DEFS_ONLY` 仍用于既有 ABI 常量。
临时的 `file` 仍是解析器借用游标，`tcc_state`、词法游标/宏展开栈、类型/符号及代码生成状态
仍有全局定义；尚未获得并行或重入保证。不得把独立编译、自举或首个资源对象误称为
全部状态迁移完成。

下一职责按原算法边界迁移词法游标、宏展开栈、临时字符串和字符分类表，再迁移语法/符号/作用域，
随后迁移目标代码生成、链接输出和装载资源。跨对象操作使用 `vo_*`，通过参数传递
协作上下文，不增加新的全局服务定位器，也不把所有状态堆进一个会话对象。
每步替换活跃路径、删除被替代实现并重跑差分和阶段稳定性验证。

## 参考树独立性

根构建只在参考树存在时声明可选 `tinycc_baseline` 目标。`tests/independent.py` 每次创建
新的源码副本，只复制 NeoCC、运行库、仓库内运行时/生成器及必要回归输入，不复制
`tinycc/` 或既有构建缓存；在该副本中构建、执行九组回归和阶段自举。
这验证文件和工具依赖的独立性，不等于剩余算法已经完成对象化迁移。
