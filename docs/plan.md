# NeoCC 后续阶段计划

本计划以 2026-10-20 完成的 switch/case 对象迁移为起点，记录后续阶段及完成状态。
P01、P02 已完成；当前下一阶段为 **P03**。实际完成情况以源码、[交接记录](handoff.md) 和本阶段
重新执行的验证为准；本文件中的计划不代表功能已经实现或平台已经验证。

## 接手与执行方式

1. 先读 [Agent 指南](../AGENTS.md)、[交接记录](handoff.md)、
   [架构](architecture.md)、本计划和对应源码，重新检查 Git 工作区。
2. 后续收到继续迁移的指示时，按开发者指定的阶段执行；未指定编号时，选择顺序最前、
   前置条件已满足的未完成阶段。每次完成并验证一个阶段后停下。
3. 每次只完成一个职责清晰的阶段，包含实现、旧路径删除、必要回归和文档同步。
   阶段不是对象数量要求；按真实所有权复用或增加对象，不把字段统一塞进新外壳。
4. 实施前复核下表中的状态和入口。若一个阶段经代码分析仍过大，先按完整职责拆成
   `Pxx.1`、`Pxx.2` 等子阶段，写明依赖与验收条件，再完成一个子阶段后停下。
   保留已有编号，避免后续对话引用失效。
5. 完成并验证后，同步本表状态、下一阶段入口、`handoff.md` 和其他受影响文档，
   说明实际通过范围与未验证项，给出一句中文提交信息，然后停下。Git 由开发者操作。

已完成的 `source`、`tokens`、`preprocessor` 工作区、`symbols`、`expressions`、
`scopes`、`functions`、`switches`、`initializers`、`temporaries` 所有权迁移不重新实施。现有阶段自举和无 TinyCC
参考树的独立构建已经建立，后续应持续维护，不另当成尚未开始的基础设施阶段。

## P01：初始化器工作区与资源（已完成）

- 阅读入口：`src/compiler/tccgen.c` 的 `initstr`、`global_expr`、`parse_mult_str`、
  `decl_initializer`、`decl_initializer_alloc`，以及 `include/neocc/preprocessor.h`
  中的通用字符串契约。
- 工作：按初始化器职责迁移跨调用存活的字符串、模式及实际拥有的暂存资源，替换全部
  活跃调用点和全局定义；`initstr` 也用于属性、汇编字符串等解析，这些消费者必须一起
  适配，并据实际共享关系确定所有者。局部 `init_params` 的引用不机械对象化。
- 完成条件：普通、嵌套与诊断跳转路径均由明确的所有者释放资源；不再依赖对应文件级
  工作区。通用局部字符串登记由已完成的 P02 处理；P01 本身不涵盖全部临时清理。
- 重点回归：拼接字符串、宽字符串、指定初始化、复合字面量、柔性数组、静态/自动
  存储期初始化、嵌套初始化错误和分配失败；保持输出、布局与目标字节行为。

已完成：`initializers` 对象拥有共享拼接字符串和全局复合字面量模式；所有字符串消费者
借用同一工作区，正常、诊断收尾和末次关闭均清理。初始化器重放流继续由 tokens 分配域
和预处理宏栈管理，局部 `init_params` 保留。新增对象/语义/故障回归、构造再生和阶段
自举验证；实际平台与范围见 [验证范围](testing.md)。

## P02：临时字符串登记与诊断跳转清理（已完成）

- 阅读入口：`src/compiler/libtcc.c` 的 `stk_data`、`nb_stk_data`、错误处理路径，
  `src/compiler/tcc.h` 的 `cstr_new_s`、`cstr_free_s`，及其全部调用点。
- 工作：为跨语法、预处理、汇编调用的临时登记提供明确的会话所有者和作用域协议，
  删除全局登记数组与计数。诊断前清理仍存活的局部资源，不能等 longjmp 后再访问局部地址。
- 完成条件：登记、撤销、跳转前清理及末次关闭配套；对象分配失败先返回 VO，再诊断；
  不新增兼容宏或另一份登记表。
- 重点回归：各模块的嵌套临时字符串、登记扩容失败、未完整初始化时的错误、分配域边界、
  连续编译与错误后新会话恢复。

已完成：`temporaries` 拥有稳定的临时字符串描述符、缓冲和编译边界；PUSH/POP、
ENTER/UNWIND/LEAVE/reset 均经 VO。删除全局登记数组、计数和 `_s` 宏；
汇编、调试、生成源码、诊断和驱动局部字符串全部迁入。正常退出严格 LIFO，诊断跳转前
释放当前边界内资源，末次关闭兜底清理，不保存 C 调用栈地址。每条记录单独分配，
不再有登记表扩容；回归逐层注入记录/边界分配失败并覆盖深层嵌套和诊断格式化失败。
实际验证范围见 [测试](testing.md)。

## P14：驱动、配置、诊断与会话入口收敛

- 阅读入口：`src/main.c`、`src/compiler/libtcc.c`、`libtcc.h`、`tcc.h`，重点是
  选项、搜索路径、输入列表、诊断回调、setjmp/longjmp 和对象创建/销毁路径。
- 工作：将剩余驱动配置和会话生命周期组织为明确组合，清除活跃编译路径最后的
  `tcc_state` 依赖、隐式状态宏和被替代字段；主机、目标、字长、ABI、格式分别表达。
- 完成条件：不存在依赖旧全局入口的活跃算法或替代它的服务定位器。进程级分配器钩子、
  诊断开关等逐项判断并记录作用域，不凭“全局变量数归零”宣称完成。
- 重点回归：CLI 选项组合、库接口、创建/open 失败、部分关闭、早期诊断、回调上下文、
  多输入和错误后新会话恢复；不未经设计与实测就宣称重入或线程安全。

## P15：当前组合的迁移闭环审计

- 工作：逐项审计可变状态、资源、借用和协作调用，检查是否仍有旧算法壳、重复路径、
  遗漏条件分支或失效文档；按实际职责清理目录、命名与内部接口。
- 完成条件：对当前支持组合给出所有权和调用关系证据；逐项记录保留的进程级设施及
  尚未验证的分支。`tinycc/` 仍只作可选基线，不作为生产依赖。
- 验证：完整差分、诊断/失败清理、构造再生、第二/第三阶段稳定性、运行库比较及
  无参考树的干净构建均通过。现有自举闭环继续维护，不能用自举通过替代架构审计。

## P16～P18：后续扩展里程碑

### P16：Linux x86-64 主机与 ELF 目标组合

- 从根 `xmake.lua`、`config.h`、运行支持与测试脚本开始，明确 Linux 主机配置、SysV
  ABI、ELF 链接/装载、系统库与运行库输入；不得只移除当前平台检查。
- 仅使用仓库内材料；缺少运行支持时列明缺项，由开发者补入仓库，不读取外部项目。
- 完成条件：在实际 Linux 环境完成 Debug/Release 构建、运行、差分、构造再生、阶段
  自举及无 TinyCC 参考树验证；Windows 原有组合继续通过。

### P17：其他目标与 ABI

- 每次只选择一个明确的主机/目标/字长/ABI/格式组合，先在本表下登记子阶段及所需材料。
  其他后端尚未迁入活跃 `src/compiler/` 的部分，按需从仓库内参考树摘选并维护来源许可。
- 完成条件：配置、后端、链接、运行库和 ABI 样例配套，明确本机执行或交叉运行证据。
  无法执行目标程序时只报告构建范围，不宣称已通过运行或自举验证。

### P18：TLS、线程及复杂运行场景覆盖

- 按 TLS/pthread、回溯、边界检查、多 DLL、ELF 动态链接等独立职责登记子阶段；
  核对各自需要的平台、运行库和编译配置，不把这些功能捆绑为一次任务。
- 完成条件：新增正向、错误和资源清理回归；逐项复核差分排除列表，只有满足条件并
  实际验证的输入才恢复到覆盖范围。共同失败不作为功能正确的依据。
- 编译器并行或重入属于独立设计决策，不由线程程序能运行或全局入口移除自动推出；
  如需实施，应另列运行时、OID、访问记录、回调与共享资源的同步和生命周期阶段。

## 每个实现阶段的共同验收

- 保持原有 C 语义、ABI、对象格式与直接代码生成；完成职责迁移所需的最小完整变更，
  删除被替代路径，不保留双实现或历史 API 兼容层。
- 对象消息经 VO，检查长度、容量和实际数量；覆盖失败不发布半成品、借用失效、
  reset、共享打开、部分关闭及诊断跳转。对象内部不得跳过 VO 清理直接 longjmp。
- 按改动补充有效的仓库内回归；新增活跃源码、对象或测试时同步根构建、
  `tests/bootstrap.py`、`tests/regression.py`、`tests/verify.py` 及其实际数量。
  新构造区经仓库 OpenOICC 预览后显式写入，重复再生保持稳定。
- 在当前支持组合串行运行以下命令，失败修复后复验；新平台的验证命令在对应阶段落地
  并写入构建文档，不能假定当前 Windows 验证脚本已经支持新平台。

  ```sh
  python tests/verify.py --mode debug
  python tests/verify.py --mode release
  ```

- 同步 `AGENTS.md`、本计划、`docs/handoff.md` 及受影响的架构、构建、测试、README
  和来源记录。检查相对路径、许可、UTF-8/LF 和 `git diff --check`。
  纯文档任务只执行文档检查，不为其重跑编译器全量验证。
