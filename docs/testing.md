  类型、嵌套作用域/标签/局部 extern、结构体/浮点/可变参数 ABI、VLA、对齐、指针及

  for/switch 的 break/continue、语句表达式清理。函数样例覆盖大结构体返回、十个结构体
  实参、递归/间接/内联调用、变参浮点、旧式参数、函数指针返回、VLA 参数和 `__func__`。
  switch 样例覆盖多 case 的线性/二分查找、相邻范围合并、GNU 范围、64 位无符号边界、
  嵌套 switch、break/continue、空 switch/default 和代码抑制。初始化器样例覆盖窄/宽字符串
  拼接、内嵌零、指定初始化、柔性数组、静态/自动复合字面量、嵌套数组、section/alias
  属性、汇编拼接字符串及静态断言。
- 对同一输入比较 TinyCC/NeoCC 预处理文本，以及无调试信息、`-g` 和 `-gdwarf-5`
  三种选项下的 ELF 目标字节，包含预处理、语义、作用域、函数、switch、初始化器、临时字符串及翻译单元样例。
- 包含链与 `#line` 诊断、缺失文件、输出失败，比较错误退出和诊断内容。
- NeoCC 编译并实际运行 NEOioic 分派、健壮性、菱形继承和本项目源对象/token 对象/预处理对象/符号对象/表达式对象/作用域对象/函数对象/switch 对象/初始化器对象/临时字符串对象/目录测试。

- 延迟内联样例覆盖递归、互相引用、传递引用、未引用定义不链接外部调用、后续声明

- TinyCC `tests/tests2` 的 120 个输入逐项差分；21 个平台特定或需要本阶段未启用运行库的输入明确排除，

## 自举及构造再生

`tests/bootstrap.py` 从 GCC 构建的第一阶段 NeoCC 开始，以普通 C 源码独立编译
CLI、宿主、源对象、所有当前后端/编译模块和 NEOioic，链接第二阶段；再用第二阶段
构建第三阶段。各阶段还重新编译运行库和 OpenOICC。

第二/三阶段的 26 个 NeoCC/NEOioic 目标文件、NeoCC 可执行文件和 OpenOICC
可执行文件共 28 对逐字节一致；`libtcc1.a`、`runmain.o` 也逐阶段比较。
不启用调试路径或时间戳等可变字段，不以修改预期哈希掩盖差异。
`bootstrap/results.json` 记录本次产物 SHA-256，不提交本机绝对路径。

第二、第三阶段均编译运行额外的延迟内联资源测试和多文件语义样例。

## 不含 TinyCC 参考树的验证

`tests/independent.py --mode debug`（或 `release`）每次建立全新的仓库内源码副本，
不复制 `tinycc/`、现有产物或缓存。在副本中用 GCC/xmake 构建，执行二十六组根回归，
再以 NeoCC 完成第二/三阶段编译、运行库重建、28 对输出比较、十一个对象的构造再生及延迟内联资源回归。
两种模式的独立性结果位于 `build/independent/debug.json` 和 `release.json`。
完整验证入口包含该检查；独立性副本不运行需要参考语料的 TinyCC 差分。
它证明构建和运行不依赖参考树，不能证明全套对象化重写已经完成。
